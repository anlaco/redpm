# redpm Roadmap

Hoja de ruta para el desarrollo de redpm - Red Package Manager.

## Estado Actual: v0.1.0 (MVP)

✅ Funcionalidades implementadas:
- Inicialización de proyectos (`init`)
- Instalación de dependencias desde Git (`install`)
- Actualización de paquetes (`update`)
- Eliminación de paquetes (`remove`)
- Listado de dependencias (`list`)
- Formato simple deps.red

---

## Fase 2: Versionado (v0.3.0)

> **Objetivo**: Builds reproducibles

### 📌 Versiones específicas
- [ ] Soporte para tags de Git: `Red-Serial ["url", tag: "v1.0.0"]`
- [ ] Soporte para branches: `Red-Serial ["url", branch: "develop"]`
- [ ] Soporte para commits: `Red-Serial ["url", commit: "abc1234"]`
- [ ] Sintaxis corta mantiene compatibilidad: `Red-Serial "url"` = última versión

### 🔒 Lockfile
- [ ] Generar `deps.lock` con versiones exactas (commits)
- [ ] Comando `redpm install` respeta lockfile si existe
- [ ] Comando `redpm update` regenera lockfile
- [ ] Comando `redpm install --no-lock` ignora lockfile

### Formato deps.lock propuesto:
```red
[
    ;-- Auto-generated by redpm - DO NOT EDIT
    ;-- Generated: 2026-01-31
    Red-Serial [
        url: "https://github.com/ANLACO/Red-Serial"
        commit: "a1b2c3d4e5f6..."
        installed: 2026-01-31T10:30:00
    ]
]
```

# Bugs
- Windows: `.git` dentro de deps puede quedar sin poder borrarse por permisos; remove no elimina totalmente y futuras instalaciones detectan la dependencia como ya instalada.
  - Reproducción: Windows, git clone de un paquete, luego `redpm remove <pkg>` → `.git` queda.
  - Impacto: alto en Windows (requiere borrado manual).
  - Workaround: borrar manualmente o usar PowerShell `Remove-Item -Recurse -Force`.
  - Priorización: pendiente (v0.1.1 bugfix).
  - Responsable / notas: implementar `delete-dir-force` + verificación de instalación corrupta.
